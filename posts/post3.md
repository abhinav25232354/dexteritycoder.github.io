# Train to Thoughts

Deliberate practice is the fastest way to turn knowledge into skill. Here's how to structure your learning.

## The Gap Between Learning and Doing

Reading tutorials is easy. Shipping projects is hard.

The gap exists because **learning is passive** but **doing is active**. You must build things to really learn.

## Deliberate Practice Framework

### 1. Choose a Skill
Pick one specific thing: "Build web apps" or "Master React" or "Deploy with Docker."

### 2. Design Small Projects
Projects should:
- Be **achievable in 1-4 weeks**
- **Force you to learn** new concepts
- **Increase in difficulty** over time

### 3. Build With Focus
- Minimize distractions
- Read docs, don't copy-paste blindly
- Make mistakes intentionally to learn failure modes

### 4. Reflect & Document
- Write a brief post-mortem: "What went well? What was hard?"
- Document decisions and trade-offs
- Teach someone else what you learned

## Project Progression Example

**Phase 1: Fundamentals** (Weeks 1-2)
- Build a static HTML/CSS site
- Learn flex layout, responsive design

**Phase 2: Interactivity** (Weeks 3-4)
- Add JavaScript event handlers
- Fetch data from an API
- DOM manipulation

**Phase 3: Architecture** (Weeks 5-8)
- Build with a framework (React, Vue)
- Component design, state management
- Routing and navigation

**Phase 4: Real-World Patterns** (Weeks 9-12)
- Authentication and authorization
- Database design and queries
- Error handling, logging, monitoring

## Measuring Progress

Track progress through:
- **Shipped projects** — Deployed, working, live
- **Code quality** — Fewer bugs, cleaner architecture
- **Speed** — Same task takes less time to build
- **Confidence** — Comfortable with new problems

## The Role of Theory

Don't neglect theory, but balance it with practice:
- **70% doing, 30% learning** for sustained growth
- Read before building to understand patterns
- Revisit theory after shipping to deepen understanding

Remember: **The best way to learn is to build something you care about and ship it.**
